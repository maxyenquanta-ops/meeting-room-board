# 會議室預約看板（meeting-room-board）

放在**一台共用辦公電腦**上的單機看板兼預約終端。同事走到這台電腦前，用桌面瀏覽器
查看 3 間會議室當日的預約狀況，並直接以「填名字 + 主題」的方式預約。

- 純前端、零後端、零外部網路請求，斷網也能用。
- 資料只存在這台電腦這個瀏覽器的 `localStorage`，不做帳號、不做跨裝置同步。
- 刻意做到最小：只有單日檢視、3 間會議室並列、整點時段。

> 詳細需求與非目標請見 [`spec.md`](spec.md)（繁體中文需求規格，是行為的最終依據）。
> 開發約定與領域規則請見 [`CLAUDE.md`](CLAUDE.md)。

## 功能清單

- **當日看板**：3 間會議室並列為 3 欄，左側為 09:00–18:00 的整點時間軸，每格顯示
  空閒或已預約（顯示預約人姓名、會議主題、時段）。
- **標示今天與現在**：日期為今天時顯示「今天」徽章，看板上畫一條紅色「現在時間線」，
  並高亮目前所在的時段列；每分鐘自動更新。
- **切換日期**：以「◀ / ▶」在工作日之間前後切換，「回到今天」一鍵跳回；週六、週日
  顯示為休息、不開放預約。
- **新增預約**：點空閒時段開啟表單，填開始/結束時間（整點、結束須晚於開始）、
  預約人姓名（必填）、會議主題（必填）。送出前做衝突檢查。
- **修改預約**：點既有預約可改姓名、主題、起訖時間，衝突檢查會排除自己。
- **取消預約**：看板上每筆預約右上角的「取消」，或表單內的「取消預約」，皆需二次確認；
  任何人都可以改或刪任何一筆。
- **衝突攔截**：同一間會議室、同一日，任兩筆預約不可在任何一小時重疊（跨多小時的
  預約占用範圍內的每一小時）；不同會議室或不同日期的同時段互不影響。
- **本機持久化**：所有預約存於 `localStorage`，重新整理或關掉瀏覽器再開仍在。
- **匯出 / 匯入 / 清除**：
  - 匯出 JSON — 下載目前全部預約（備份或換機用）。
  - 匯出 CSV — 下載目前檢視日期的預約清單（會議室、時段、預約人；含 UTF-8 BOM 供 Excel 開啟）。
  - 匯入 JSON — 於同機以檔案內容「整批取代」目前資料，匯入前二次確認。
  - 清除全部 — 清空所有預約，需二次確認。

## 如何開啟使用

不需要安裝、不需要建置工具、沒有 `package.json`。

1. 取得這個資料夾（`index.html`、`app.js`、`test.html` 三個檔案需放在一起）。
2. 用桌面版 Chrome 或 Edge（近版）開啟 `index.html`：
   - 直接在檔案總管**雙擊** `index.html`，或
   - 放到公司內網的靜態網頁主機上，用網址開啟。
3. 就能看到當日看板，點時段即可預約。

資料綁在「開啟它的那個瀏覽器」。換電腦或換瀏覽器要保留資料，請用「匯出 JSON」再到
新環境「匯入 JSON」。

## 如何執行測試

測試涵蓋 `app.js` 的衝突檢查函式 `hasConflict()`（完全重疊、部分重疊、包含、
緊鄰、不同室、不同日、修改排除自己等案例）。

1. 用瀏覽器開啟 `test.html`（雙擊即可）。
2. 頁面頂端會顯示「通過 N 項／共 M 項」，全綠即為通過；任何失敗的案例會以紅色列出
   預期值與實際值。

沒有測試框架，也不需要指令列；`test.html` 自己就是 runner。

## 檔案結構說明

| 檔案 | 說明 |
|------|------|
| `index.html` | 應用主體。包含全部 HTML/CSS 與大部分 inline JS：常數（會議室清單、營運時段 `OPEN_HOUR`/`CLOSE_HOUR`、`STORAGE_KEY`）、`localStorage` 存取、日期工具、看板渲染、預約表單、匯出/匯入/清除、事件綁定與啟動流程。 |
| `app.js` | 只放預約衝突判斷邏輯 `hasConflict()`。由 `index.html` 以一般 `<script src="app.js">` 載入（**非** ES module，這樣雙擊檔案開啟也能用），讀取 `index.html` 宣告的全域 `state.bookings`。 |
| `test.html` | 衝突檢查的測試頁。載入 `app.js`，自備一個替身 `state`，跑一組案例後把結果渲染成表格。 |
| `spec.md` | 繁體中文需求規格，功能與非目標的最終依據，含 §7 的 10 條驗收標準。 |
| `CLAUDE.md` | 給開發者（與 Claude Code）的指引：三檔限制、繁體中文慣例、領域規則。 |
| `bugs.md` | 已知問題與點交紀錄。 |

### 開發約定（重點）

- **只有這三個檔案**：`index.html` + `app.js` + `test.html`，都在專案根目錄。不再拆出
  其他 `.css` / `.js`，不引入任何框架或函式庫（不用 React、Vue、jQuery、Tailwind 等）。
- **全繁體中文**：所有 UI 文字與程式註解都用繁體中文。
- 純前端、離線可用；不呼叫任何外部網路服務。
- 營運時段 `09:00–18:00` 與會議室名稱「會議室 A / B / C」是可調整的常數，寫在
  `index.html` 上方。

### 資料模型

```js
booking = {
  id,         // 唯一字串（crypto.randomUUID 或退化亂數）
  roomId,     // 'A' | 'B' | 'C'
  date,       // 'YYYY-MM-DD'
  startHour,  // 整數，整點
  endHour,    // 整數，整點，須嚴格大於 startHour
  name,       // 預約人姓名（必填）
  topic,      // 會議主題（必填）
  createdAt,  // ISO 字串
}
```

全部預約以陣列形式存在 `localStorage` 的 `meeting-room-board/bookings/v1` 鍵。
